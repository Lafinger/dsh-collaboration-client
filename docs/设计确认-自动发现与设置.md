# 自动发现、默认启用与协作接入设置：设计确认

本文保留0.4.0的设计历史；项目面板位置、单项入口及刷新方式已由[0.5.0菜单设计](<设计确认-模型菜单项目选择.md>)替代。连接发现和设置／项目归属分离的规则仍保留。

## 已确认（用户：Q4只配置连接与身份，其他都按建议来）

- 使用当前用户 `.dsh/dsh-collaboration-client`，不写死Windows用户名。
- 默认优先读取顶层标准成员配置；没有可用顶层配置时，只发现一级子目录内同名配置。唯一可用候选自动采用，多个候选有歧义时由成员在设置页选择，不按文件修改时间或昵称猜身份，不合并文件。
- 免手工文本编辑不等于可以推测连接。设置页提供配置选择、导入与保存选择；只保存插件自己的状态，不自动改现用profile patch或覆盖成员已有配置，不读私钥正文。
- 新安装默认启用组件，尊重用户已有禁用；启动不自动SSH、扫码、消息发送或模型调用，不替换当前默认模型。
- DSH设置侧栏新增“协作服务”，面板仅连接与身份：配置来源、连接信息、扫码开始／领取、状态刷新／退出当前设备。不得将项目、会话、历史和通信放进此设置页。

## 事实与待确认分支

- 现成员实现创建登录后的新远端会话前必须有显式项目选择；不允许SSH-only回退或猜项目。
- 项目选择、本人历史和通信此前与登录混在同一个面板；缩小设置页后须确认另设普通会话入口，还是本轮只交付接入验收并不提供业务入口。不能静默删掉选择而声称业务可用。
- 旧版可显式配置configFile、环境和内联资料；应确认与新设置页保存的选择之间的优先级及变更方式，不自动改profile。
- 正在业务执行或已登录时切换连接涉及撤销设备登录及会话归属；应确认禁止忙时切换、明确退出后才切换、不迁移旧mapping的规则。

进一步将同一个官方ClientModuleSystem交给真实Cordis Loader1.0.5，调用与Web启动内核相同的entries.start，再进行Host图移除／加入。0.3.1实际entry处于ACTIVE，所需服务为connection和slots，菜单注册／移除／再注册均通过，RPC0。证据位于隔离 `.dsh/evidence/official-entry-start-baseline.json`。第一次诊断错误地把ClientEntries.state当普通对象，按官方Store的getSnapshot接口修正后重跑通过；未把诊断脚本自身错误算成插件故障。

## 实施中的链路核验

- 官方Host默认bundle经Loader真实挂载、浏览器图可见；用户后置`disabled:true`使组件与浏览器图撤回。开启时未连接SSH、未登录。
- 官方ClientModuleRegistry／ClientModuleSystem→entries.start→SlotRegistry→官方设置壳，在JSDOM真实React DOM中点击“设置／协作服务”，验证菜单和身份面板、图移除与再加入。展示图标／基础外观组件为惰性替身，未对现用GUI截图进行验收。
- 官方buildModelCatalog与ModelDirectoryResolver／ModelSelect，经当前会话作用域点选“Collaboration → 项目选择”，验证只在选中后挂载项目区，未调用真实模型或消息。该测试发现项目区状态Hook缺少selector会崩溃；按官方Hook契约修复，保留渲染断言。
- 配置指纹变化时，Host RPC、模型转发及自动恢复均失败关闭；明确退出仍可撤销原设备，不采用另一个账号。无密钥正文或登录token进入浏览器／选择状态。
- 本轮不修改宿主设置壳，不重装现用profile，不更新Linux部署。新包仅本地生成，GitHub旧标签保持原样。
