# 本地附件传输与项目资料归档

## 当前工作区状态与能力边界

本页描述客户端主干的**v4自然语言附件流程**；历史版本说明见[发布记录](<RELEASE.md>)。发布不表示当前运行中的插件、GUI或服务已经升级；客户端由用户安装，服务端需配套支持humanAuthorization v3与附件扩展v2，部署与真人／真实模型验收另行完成。

本轮通用文本读取、正文限额取消、历史派生解析缓存刷新与关联说明边界主要由配套服务端 `0.7.2-rc.9` 实现；客户端 `0.6.3-rc.8` 仅删除未使用的256KiB常量并同步说明，**不新增客户端解析执行**。发行状态以各自标签CI与GitHub Release为准，部署另行核实；下述行为不表示线上服务或已安装客户端已可用，不作为真人／真实模型验收通过的证据。原有协议配对、上传与安全边界保持，旧 rc.7 仍兼容协作v4／附件扩展2／人类授权3，不要求清登录或会话映射。

双端必须协商 `humanAuthorization.version: 3` 与 `attachmentTransfer.version: 2`，基础协作协议v4；不匹配的peer在initialize即拒绝，**不会读取并上传文件后再降级，也不会伪造旧模板或自动重发业务prompt**。离线测试与能力声明不是现实模型、用户GUI或已部署服务验收。

## 日常操作：说用途，不填授权参数

附件只在**已绑定项目**的Collaboration会话中处理。项目只能通过模型菜单明确选择（`client.selectProject`），会话消息里的文字不再创建或猜测项目绑定。绑定后，添加聊天文件／图片，或明确选择当前会话工作区内的单个 `@路径`／`@"含空格的路径"`，然后自然说明：

- “请归档这份附件并整理要点。”
- “先阅读，不要归档。”
- “把刚才那份归档。”——先阅读后再说明归档意图时，本轮重新随消息提交v3授权元数据；没有自动重传。
- “请把这份文件作为《requirements.md》的新版本归档。”——需要服务端真实资料目录中精确、唯一的目标；不按文件名里的v2等字样猜测。

未绑定项目的会话里发送附件会**当场失败**（提示先在模型菜单选择项目），不上传任何字节、不发送业务请求；纯文字消息照常转发，不带附件元数据。

文件路径须在**当前本地会话工作区**内，不扫描目录；拒绝工作区外文件、目录、symlink/junction、`.dsh`／`.ssh`／`.git`与常见凭据／私钥路径。不读取文档里提到的其他文件。最多5份文件，单文件与每消息总计20MiB。文件必须非空；候选 rc.7 对空文件和不存在路径显示具体中文原因，保存内容或修正文件名后以新消息重新上传。

## 版本、草稿与真实结果

最新内容相同不新增版本；内容变化按材料规则追加版本；命中历史旧内容返回冲突错误，当前流程没有恢复确认旁路。客户端本地字节读取只在发送消息期间有效；服务端已上传的附件按账号和会话持续保存，后续消息可引用同一 handle。

归档不分配人员、不批准方案、不自动激活或完成任务。分析准备／整理要点／方案草稿不等于正式登记分析；只有实际正式提交成功才宣布登记。文件名中的版本号也不等于资料版本号。

日常结果按资料名、版号说明，不要求复制内部ID、工具JSON或服务器路径。确定“业务未开始”、已核实的部分成功与“整体结果未知”分别表达；已发送失败仍保持宿主错误状态，不用正常完成冒充成功，也不承诺所有宿主状态标记消失。

## 原件、格式与技术传输边界

字节在服务端模型回合开始前通过反向 RPC `collaboration/attachment/read` 拉取并校验，模型随后用 `attachment_read` 读取、`attachment_archive` 归档。客户端只提供当前 session/request/handle 对应的文件块；同内容归档去重，跨轮引用不自动重传本地旧文件。

本轮普通文本不按后缀限制：HTML／CSS／JavaScript／JSON／XML／日志／无后缀等文本按内容判定，支持严格UTF-8（含BOM）及带BOM的UTF-16 LE／BE。解码后拒绝NUL与非文本控制字符，保留正常制表符、换行；后缀、MIME、HTML charset不决定可读性，不自动猜GBK或无BOM的UTF-16。无法可靠解码时明确报告不属于受支持编码的文本或为二进制，并提示转存UTF-8；改成TXT后缀不能绕过判定。

HTML等按原文返回，不去标签、不渲染、不执行脚本、不fetch或加载外链、不跟读正文中的路径。静态源码读取不证明浏览器运行或验收通过，文件内容也不构成人类操作授权。

既有DOCX及单帧PNG／JPEG／WebP专用能力保留，不将任意二进制硬解码成文本，本轮不新增PDF／XLSX／PPTX／压缩包等二进制解析。**GIF禁止上传**：名称、声明类型与收到字节均校验，改扩展名也拒绝，不提首帧／转码绕过。DOCX仍只提正文／表格，不执行宏或加载外链，嵌入图片与修订仍列缺口，不自动进入视觉模型。格式完整性、图片尺寸等既有校验不变。图片是否能被实际模型理解仍取决于已验证的服务端能力，不因传输／归档成功就宣布视觉分析成功。

取消附件读取、资料读取与分析读取的正文256KiB限额，包含DOCX提取正文；服务端默认完整返回，不因正文大小拒绝、不截断、不分页、不分块或自动摘要。原件上传仍是每消息最多5个、总计20MiB、单文件20MiB，并不随正文限额取消而扩大。完整返回正文不等于模型已逐项检查全文，更不等于实际运行／验收；模型上下文、传输与资源等外部限制另行区分，可观测错误如实报告，不声称全文已读，不静默裁剪。

DSH原生image可能已经归一化，丢失来源时不能从PNG字节识别其曾为GIF；原件保真请使用file附件或明确路径。历史图片仍须当前真人明确用途、核实同账户／会话／项目原件，不以旧历史或模型回答自动重发。

## 历史解析缓存与关联说明

历史附件和归档资料在实际读取时按解析器版本刷新：旧版缓存（含曾标记未解析的HTML）从保存的原件重新解析并核实原件sha256，当前版本缓存可复用；归档去重、无提取缓存的读取路径使用同一判定。不要求重传、不批量扫描全库，只刷新可再生成的派生（derived）解析缓存；不改原件／哈希、资料身份与版本，不新增资料版本，不迁移或重写历史分析及正式决定。原件缺失、损坏或哈希不符明确报错，不能以缓存或说明冒充原件已读。

原件不可读时，可单独读取用户明确指定的可读说明：用户在消息中显式配对已上传文件，或使用系统已有的明确关联；归档资料要指定资料ID和版本，成果沿用固定版本的摘要、自检与附件清单。本轮不新增关联表或自动找说明工具，不按同名、同目录或正文路径自动关联、扫描或跟读；指定说明缺失就报缺失，不自行另找。

正式分析的原件与说明都须显式列入 `scope`，关联不自动扩大分析范围。结果须分别说明原件可读性、实际读取的说明，以及仅由说明支持而未核实原件的结论；读取说明或下载原件不等于读取原件，原件未读缺口仍保留。

## 断线与只读核实

保留已有本地／远端会话映射，不自动重发旧消息、上传或归档。可只读核实本会话回执、资料版本与项目进度；恢复历史调用不是新的业务授权。收到原件但未归档时，可在同一会话自然说明继续；原件确实不可用才要求重新选择。换账号／会话不能读取别人的接收回执，正式共享资料仍执行原项目权限。
