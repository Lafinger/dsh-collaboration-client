# 本地附件传输与自动资料归档

客户端0.3.0配合服务端0.4.0（本地实现完成，正式发行/部署验收待定）；DSH0.2.0-rc.2。原有文本会话协议v2保留，新附件扩展版本1必须双方精确支持。不支持时拒绝本条附件请求，不降级、不重发业务prompt。

## 操作

先核对项目ID。添加聊天文件/图片附件，或在当前人类消息写工作区内的 `@路径` / `@"含空格的路径"`。**单独写一行授权操作和唯一项目ID**：

```text
附件操作: 上传并归档
project_id: <32位项目ID>
@"测试材料\项目需求\需求文档.docx"
请传输这个文件，读取并判断用途/所属角色，登记到合适的资料目录；
分析需求、矛盾、待决问题和所需角色，不分配人员，不创建/确认计划或任务。
```

原生聊天附件可以省略路径。仅传输先不登记用 `附件操作: 仅传输`。操作行需与其他文字分行，不要使用两种操作或两个项目ID。客户端按当前消息建立授权，不把历史聊天、模型回答、文件占位符中的路径当成权限；对“不要上传”等自然语言不猜权限，必须明确上述操作行。

文件路径必须在**当前本地会话工作区**内（会话工作区不等于插件仓库目录）。不扫描目录，拒绝工作区外文件、目录、symlink/junction、`.dsh`/`.ssh`/`.git`及常见凭据/私钥路径。不读取文档内容提到的其他文件。最多5文件、单文件及每消息总计20MiB。

## 工具链与结果

远端Agent调用 `attachment_transfer → attachment_inspect → attachment_archive`。客户端只返回当前session/request/opaque句柄的文件块；服务器校验hash/长度、保留接收到的原件，解析后由模型给用途与role/共享及依据，服务器生成受限目录。

`attachment_archive`不分配人员、不批准方案、不创建任务；同一回执再次归档只返回原版本。DOCX/MD/TXT正文分析走已有服务器模型；解析产物绑定原件hash与固定资料版本，文件名中的版本不等于资料版本号。

支持DOCX、严格UTF-8 MD/TXT、PNG/JPEG/WebP/GIF。DOCX提取正文/表格，但不渲染页面、不读取外链、不理解嵌入图片；修订和缺口明确报告。图片首版传输/格式/尺寸/首帧校验与归档，**没有视觉分析/OCR工具，不切换模型**，不能假称看懂图片。DSH原生image可能已归一化，接收字节不保证是浏览器上传前原件；需原件保真用file附件或显式路径。其他格式可保存原件但解析明确未覆盖。

## 断线与恢复

不要重发旧消息。保留客户端本地/远端映射数据库，恢复同一远端会话，通过 `attachment_receipts`查本账号本会话最近100条回执，再inspect已经传好的附件/检查material版本。传输失败不重放prompt，不自动再归档；收到回执但未归档可在同一会话明确继续。换会话/换账号不能读取他人接收回执，但已正式归档资料仍走原项目共享规则。
