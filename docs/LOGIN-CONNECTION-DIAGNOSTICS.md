# 0.4.2：发起扫码时报Connection ended的诊断修复

## 已知与未知

用户升级0.4.1后，本机配置、来源、服务／账号与SSH入口已经可读，但点击“发起钉钉扫码登录”出现`Connection ended`，没有得到登录链接。**本地配置完整只证明文件通过校验，不证明SSH、远端connector、协作Host或钉钉可用。**下拉框仍是“请选择”只代表尚未准备切换；当前连接已经采用上方显示的保存选择，不需要因此重新选配置。

已在隔离“按钮→官方Connection RPC→真实成员Host→MemberClient→openSsh→JsonPeer”回放中复现同样红字。0.4.1的SSH stderr直接继承至Host终端，stdout EOF先触发JsonPeer失败；客户端立刻kill进程，后续退出信息无法成为页面错误。因而认证失败、远端启动失败、协议握手前结束都可能显示同一个Connection ended。

**这证明诊断信息丢失，不证明用户现场一定是SSH公钥认证失败。没有现场SSH stderr或远端日志，不能声称已修复真实登录、服务器或钉钉配置。**0.4.2是安全诊断／终止生命周期修正版；未知现场根因仍需错误文本或脱敏日志确定。

## 修复

- SSH stdout／stderr仍是独立管道，普通诊断不混入NDJSON协议。stderr仅保留最多8192字符的内存尾段，识别到的分类可保留；结束后丢弃原文，不写磁盘、不继承未脱敏内容到Host日志、不返回浏览器。
- stdout结束后仅为取得close／退出码／后到stderr等待最多300ms；不再提前kill正常退出中的进程。等待期间不发送新RPC，已提交请求不重试。明确退出和非法协议仍立即终止。
- 提示为固定分类、最近请求阶段和安全退出码；仅用于判断下一步，不把远端文本当指令，不泄露私钥路径、凭据、token或proof。无法识别时明确“具体原因尚未确认”，不猜原因。
- 捕获本机SSH程序无法启动、子进程提前关闭、没有close事件、stdout污染、退出／stderr顺序；正常协议响应与登录链接不受影响。
- 不修改共享业务协议或远端connector，不关闭StrictHostKeyChecking、key-only、固定command、同源、登录或项目权限校验。无需删库、改profile或编辑成员JSON。

## 如何复测

1. 本地升级至0.4.2，完全重启DSH并刷新原页面。进入设置 → 协作服务核对配置仍可读。
2. **点击一次**“发起钉钉扫码登录”。若出现链接，才由用户自行打开可信页面扫码；不要发业务消息。
3. 若失败，提供整条新的红字（包含阶段和退出码）与组件版本截图。若仍未识别，请管理员提供该次失败附近少量SSH／connector／协作Host日志，删除token、proof、私钥、签名密钥等凭据；不要提交完整配置或日志库。

| 新提示或证据 | 下一步由谁核对 |
|---|---|
| SSH公钥认证失败，常见255 | 管理员核对成员OS账号、账号准入、授权公钥及使用的密钥；不是用钉钉扫码替代SSH |
| 主机指纹已改变／校验失败 | 管理员经可信渠道核对服务器指纹与known_hosts；禁止关闭严格检查 |
| 本机私钥不可用／程序未找到 | 本机管理员核对文件权限、密钥格式、非交互可用性或OpenSSH程序 |
| 被拒绝／超时／无法解析 | 核对SSH监听与发布端口、DNS、网络和防火墙，不任意打开公网 |
| 远端固定接入命令启动失败 | 服务器管理员核对forced-command、Node及connector安装 |
| 远端connector凭据权限／账号 | 管理员核对root所有权、成员组、0440及账号，不把凭据交给客户端 |
| 远端协作服务socket不可用 | 管理员核对协作Host运行状态、socket路径／权限及部署 |
| 远端协作协议版本不匹配 | 管理员核对当前connector与协作Host都支持扩展v3；不要降级或换账号 |
| initialize阶段，原因未确认 | 尚未收到完整握手；需要该次SSH／远端启动日志 |
| collaboration/login/start阶段，原因未确认 | 已通过握手但登录申请无完整响应；需要协作Host／登录服务日志，不能伪报扫码成功 |

这些分类只根据SSH诊断线索，不验证远端日志的真实性；最终授权仍由远端负责。没有现场证据前不修改服务器或替换密钥。

## 验证范围

- 回归先红：`node --test test/login-ssh-failure.integration.mjs`原0.4.1产生“Current symptom: Connection ended”；同一按钮调用链修复后分别显示认证、socket、版本与登录申请阶段。
- 分类、退出顺序、程序启动失败、明确退出、300ms有界等待、提前关闭、新RPC禁发、内存边界与秘密不回显都有断言。
- 真实本地Node子进程模拟stdio关闭／stderr延迟、正常initialize与登录链接、非法stdout；不运行SSH、不访问网络、不调用钉钉或模型。
- 抽取安装包重跑按钮及本地子进程链路，避免只测试源文件。旧0.4.1／0.4.0安装包保持原样。

本轮未安装／刷新现用GUI，未修改现用profile／成员配置／密钥或Linux部署，未真实SSH、扫码、调用模型、发送消息或发布GitHub标签；全程不使用subagent／workflow。没有获取此次失败的现场SSH日志，实际连接根因尚未验收。
