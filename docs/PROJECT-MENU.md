# 0.5.2：模型菜单内项目选择

## 使用与升级

安装新的本地0.5.2客户端包，完全重启DSH并刷新原Web页面；Host和浏览器必须同版。成员连接、设备登录和原远端会话映射不迁移、不清空，组件重启后需重新扫码。0.4.2的连接诊断仍保留；本轮不代安装、不修改原JSON／profile，不验证Codego或真实模型。

展开模型服务商／模型列表，Collaboration分组直接显示“项目标识 · 名称”，相同标识／名称简化。每次列表展开主动读取授权项目，关闭再打开重查，搜索／鼠标移动／重绘不重复获取，没有后台项目轮询、独立项目面板、确认绑定或刷新按钮。展开模型／推理等级的根菜单本身不是项目列表；进入服务商／模型列表才获取项目，返回根菜单后再进入也重查。

点击项目同时确定当前本地会话项目与固定协作路由，成功后模型位置显示项目，菜单对应行打勾；长标签截断、悬停完整显示。点选不创建远端业务对话、不发送消息、不保存协作全局默认。新本地会话必须重新明确选择，即使只有一个可访问项目；旧/model入口选中协作路由而没有项目时，业务仍拒绝并提示回菜单。

已有远端映射只能返回原项目；其他授权项目仍显示但禁用，换项目需新建会话。允许主动切回普通模型，项目归属仍保留。业务／项目选择中禁止切换，快速重复点击不重复提交。关闭菜单不是取消已提交选择，返回原会话按实际状态显示。

会话右下角触发按钮使用与DSH原生一致的字体／行高／间距、独立推理等级次级色、共享SVG箭头和窄屏图标；项目选中时只显示项目名称、不附带普通模型的推理等级。只恢复按钮外观，展开后的项目菜单及权限规则不回退。[样式验证](<MODEL-TRIGGER-STYLE.md>)。

## 失败与权限

未登录、正在获取、无可访问项目或查询失败只影响Collaboration分组，不阻塞普通模型。失败不使用旧项目缓存进行新选择，关闭再展开重试。项目稳定ID决定归属，改名用最新名字；原项目被撤权／删除时保留归属并显示不可访问，不自动改成另一个项目。网络查询失败不能推断项目已被删除。

确定失败不显示新勾选／成功，保留旧有效选择并在菜单报告。响应丢失或会话保存失败会显示“选择结果未确认”，不自动重试／提交业务；重开菜单读取真实状态。提交日志没有匹配事件时保留旧项目，日志冲突时停止并要求新建会话／管理员核对，不猜结果或删除用户库。服务端继续核验业务权限，菜单列表不是权限授予。

## 插件兼容与持久化

0.5.1的模型菜单明确注入remote和remote.session：官方可追踪modelDirectories以调用者作用域访问命名空间，缺声明会崩溃并回退成单个“项目选择”。设置页不因此增加模型依赖；[故障记录与复测](<MENU-INJECT-FIX.md>)。

DSH0.2.0-rc.2的官方菜单没有项目行子槽或展开刷新扩展；[浏览器入口](<../client/index.js>)以公开conversation.input.model的single槽优先级接替，使用modelDirectories、locale、框架生成的快照Hook和共享MenuSurface／MenuGroup，不修改官方安装文件或DOM文本。普通模型走原directory.select；保留分组、名称搜索、推理等级、键盘和/model原行为。插件禁用／卸载释放槽、字典、样式，恢复官方菜单；后续DSH版本需重新验证，未声明跨版本兼容。

[Host选择](<../src/project-selection.mjs>)重新核验当前登录与项目授权，绑定结果携带无凭据的连接代标识；旧账号／登录代的菜单不能选项目。选择在当前Agent的runMaintenance内执行，记录既有model/selection事件，通过Agent作用域的公开waterfall应用路由，不访问官方选择缓存、不改全局默认、不调用模型。会话事件仍只有provider/model字段，没有项目ID伪装成模型，没有新增Session事件或变更已发布事件格式。

[成员SQLite](<../src/member-client.mjs>)新增client_project_commit表：先记意图、append model/selection、等待SessionStore.flush，再事务提交project_selection／owner并清除日志。journal保留确切event seq/time，保存失败时禁止依赖业务；重开核验事件后才完成或保留旧项目。表是增量创建，保留原mapping／submission／project／device，无破坏性重建；只有新客户端执行流程支持此日志，结果未确认时不要降级使用旧版。日志出现无法核验的身份／事件冲突时失败关闭。

显示标签可以保留最近成功查询的名称，但不能用于权限或新选择；服务器每次展开和点击都重新授权。查询旧响应不会跨本地会话发布，设备token／proof只在Host内存，不进入菜单或SQLite日志。

## 本地验证边界

[菜单链路测试](<../test/official-model-project.integration.mjs>)经过官方ClientModuleRegistry／ModuleSystem／Loader、槽优先级、真实modelDirectories与官方Connection／Host Fetch、真实MemberClient SQLite；外部授权数据、普通模型选择和外观原语使用隔离fixture。覆盖刷新次数、搜索／键盘、锁定／撤权／失败、查询乱序、双击、关闭后提交、丢失响应及卸载／再加载；菜单打开身份严格绑定当前会话／成员代，切换时不因旧open状态隐式查询，旧会话已提交选择仍完成但不改新会话标签。当前选中、远端映射锁及未知状态另有[DOM快照](<../test/fixtures/project-menu.dom.json>)作为本地回归证据。它不是现用GUI的像素或真实浏览器验收。
