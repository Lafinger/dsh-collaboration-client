# 钉钉登录与当前会话项目选择

本地0.5.2实现不代表现用GUI已升级，也未发布新的GitHub标签。需要配套[协议v4](<PROTOCOL-v4.json>)服务端，旧v2／SSH-only服务明确拒绝，不自动降级。

## 设置只管理连接与身份

1. 安装新版后组件默认启用；读取当前用户 `.dsh/dsh-collaboration-client` 内标准成员配置。无需手改profile或原JSON。自动发现有歧义时在 **设置 → 协作服务** 选择；没有有效资料时可导入管理员提供的成员连接JSON。详见[安装说明](<INSTALL.md>)。
2. 核对服务、成员账号、SSH入口与可信HTTPS登录origin。SSH继续密钥登录、严格主机指纹；SSH本身不授予业务权限。扫码成员必须匹配配置账号，服务返回其他登录地址时拒绝。
3. 点“发起钉钉扫码登录”，打开可信页完成确认，再点“我已扫码，完成登录”。浏览器只显示账号、到期和状态，**不收到登录token或设备proof**。
4. token只驻留当前Host内存；Host／组件重启或最长12小时到期后重新扫码。刷新状态会主动复核服务器；退出只影响当前设备，不全局停用钉钉成员。断线时可用原连接参数的新传输撤销设备token；网络失败明确提示本机已退出、服务器撤销未确认，不伪报完成。
5. 已登录、待领取登录或执行中不允许切换成员配置；先明确退出，再选择连接并重新登录。不迁移、清空或重放旧对话。磁盘配置改变时新业务／恢复停止，退出原设备仍允许。

设置页没有项目绑定、历史查看或通信业务按钮，也没有独立主面板或插件详情“打开协作登录”入口。

## 发起扫码时连接失败

配置已可读仍不证明SSH或远端服务可用。没有得到登录链接而出现Connection ended时，扫码尚未开始；0.4.2修复SSH stderr／退出诊断丢失，以固定分类、阶段、退出码提示，不回显凭据原文。请提供整条新红字；未知现场原因需少量脱敏SSH／远端日志，不通过换账号、关闭主机指纹或删库解决。详见[登录连接诊断](<LOGIN-CONNECTION-DIAGNOSTICS.md>)。

## 已登录却只有“项目选择”

如控制台出现 `cannot get property "remote.session" without inject`，这是0.5.0菜单依赖缺失导致崩溃回退，不要反复扫码或清库。使用保留该依赖修复的0.5.2包，再按[无模型复测步骤](<MENU-INJECT-FIX.md>)确认项目行。

## 项目选择归当前会话

1. 新建DSH本地会话，展开模型服务商／模型列表，**Collaboration** 组直接列出当前成员授权项目。每次列表展开获取一次项目，搜索和重绘不重查；没有独立项目区或刷新按钮。项目不是底层模型，业务始终走服务端固定Agent。
2. 直接点选项目，成功后输入框模型位置显示项目标识／名称，菜单项目打勾；不再额外确认。未登录时只在协作分组提示去设置登录，不自动扫码或阻塞普通模型。
3. 点选同时完成当前会话项目与协作路由选择，不保存全局协作默认，不创建远端业务对话、不发送消息。新会话必须重新明确点选，只有一个项目也不自动采用。
4. 已有远端映射只能返回原项目，其他项目禁用并提示新建会话。允许主动选择普通模型而不清空项目归属；忙时不可切换。项目被撤权／删除时保留原归属并显示不可访问，网络失败不推断项目删除；不以旧缓存新绑定。服务端仍核验所有项目／对象归属。选择结果未确认时菜单明确提示，重开读取实际状态，不自动重试或发送业务。
5. 旧未绑定项目的会话不猜测迁移；撤销、重新开通或角色变更后旧上下文可能失效，请新建会话。已显示内容无法保证收回。恢复仅附加同ID已保存记录，不重新执行旧指令。

[浏览器入口](<../client/index.js>)使用公开connection／slots／locale和当前会话模型目录，[菜单](<../client/model-menu.js>)通过single槽接替、使用共享外观原语，禁用后回到官方菜单；[Host RPC](<../src/member-rpc.mjs>)限定本机Host和同源Origin，远端是业务授权权威。这不是公网配置或管理员面板。

## 验证边界

```sh
pnpm run build
pnpm run check
```

本轮使用官方Host清单→浏览器加载器→Cordis组件→真实官方设置壳和模型选择器，在隔离React DOM中验证项目行、展开刷新、点选／撤权／失败／查询乱序及卸载回退；本机状态使用真实成员组件和官方Connection编解码／Host共享Fetch路由；HTTP传输在进程内桥接，Host入站认证、远端钉钉授权数据和外观原语为测试替身。没有安装、刷新或修改你现用GUI，也没有真实扫码、SSH、模型或消息调用。组织／应用／HTTPS和成员权限由部署管理员准备，勿在聊天提交凭据。
