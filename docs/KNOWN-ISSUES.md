# 已知问题

## MVP-UI-001：管理区下拉框偶尔点击不展开

- **状态：已记录，按用户明确要求延期修复。** 用户确认：“先记录该问题，后续再修，先进行下一步测试”。不作为当前最小业务测试的阻断项，不代表已修复。
- **位置：** 设置→协作服务→创建项目与角色分配中的“项目／职责／成员”下拉框；不是会话模型菜单的Collaboration分组。
- **实际表现：** 用户报告偶尔点击后完全没有展开。尚未确认桌面／普通浏览器差异、失败时焦点与禁用状态，未取得可稳定复现的真实原生弹层反馈。
- **已完成情况：** 用户已实际完成MVPQR01项目、产品／前端两项职责及B共享可见测试；不为排查重新创建项目或重复分配职责。
- **现有实现：** [管理区表单](<../client/index.js#L72-L83>)使用三个原生HTML select。A首轮扫码客户端与B时钟修复客户端的该UI实现相同；不能归因为时钟修复。
- **现有验证的边界：** [管理表单测试](<../test/mvp-admin-ui.test.mjs>)验证选择值、创建／分配及版本提交，但直接调用onChange，并不验证Windows桌面壳是否显示原生下拉弹层。该测试通过不代表本问题被复现或修复。

后续重新开展诊断时，先捕获失败时的环境、真实点击／焦点／disabled状态及键盘Alt+↓对照，建立能抓住此症状的最小回归，再确定原因和修复。不预先认定是刷新、焦点、忙碌或宿主拦截；不以重建项目、清理登录／映射或重复管理提交绕过。

本次只记录问题：不改交互实现、不重启服务器、不代为重装客户端、不影响现有成员／角色／项目／会话。将来如修改源码，仍按GitHub提交推送、固定Windows／Ubuntu与打包CI通过及原始包核验后正式安装；不承诺源码修改会热更新当前GUI。
