# 客户端MVP：网页扫码登录最小改版

状态：**用户已最终确认“确认，按网页扫码最小改版方案开始实施”，进入非破坏性实现／验证阶段**。本文件汇总本仓需要遵守的边界，不是扫码实现／上线／验收报告。当前正式PC插件仍按原版本运行，暂停B的原PC测试与业务推进；本次先实现隔离扫码改版，不立即撤销现用登录。进度与使用门槛见[扫码实现说明](<MVP-WEB-QR.md>)。

## 1. 用户操作

```text
设置 → 协作服务 → 同一个可信HTTPS地址
  → 点“钉钉扫码登录” → 自动打开默认系统浏览器的官方授权页
  → 手机钉钉扫码并完成官方确认 → 原DSH自动显示实际登录身份
```

- 不要求安装或登录电脑钉钉，不进入工作台、不输入核对码、不点“我已扫码”。
- 不在DSH内嵌二维码，不自建钉钉账号／密码输入页面，不增加应用自己的第二次身份确认。
- 保留一个HTTPS地址，不恢复个人SSH、密钥、JSON导入或hosts修改。
- 电脑仍经既有LAN／ZeroTier到达服务；手机使用普通Wi-Fi／移动网络。不给手机增加ZeroTier要求，不新增公网入口。真实网络目标不成立时停止并另议。
- 官方页可能有其他官方授权方式；应用只依据最终官方身份认证，不声称从返回结果就能判定“只用了扫码”。实际验收使用手机扫码。

## 2. 实际授权者是登录者

当前组织有效内部成员首次授权自动登记；同人重登复用成员身份。固定陈锦鸿是管理员，只多创建项目和分配角色；普通成员可见全部共享项目，但不能代替职责本人决定或读取他人私人对话。

如果陈大海的手机为A电脑发起的请求授权，该设备就登录陈大海，而不是凭电脑使用者名称改成陈锦鸿。DSH显示实际姓名和管理员标记，误扫应退出当前设备并重新扫码；不把原成员会话、角色或映射转给另一人。只扫描本人发起的可信页面，不替别人发来的二维码／链接授权。

## 3. 7天设备资格与一次请求

| 项目 | 已确认规则 |
|---|---|
| 登录记忆 | 最长7天、固定到期，重启保留，不随使用滑动续期；Windows沿用系统CurrentUser安全加密，不降级明文 |
| 多设备／退出 | 每设备独立，本机退出不影响其他设备；离线退出清本机密文，但远端撤销未知须明确提示 |
| 组织资格 | 沿用最多5分钟有界复核，官方暂时不可用暂停业务，不延长设备资格 |
| 发起 | 同一设备只有一个当前请求，最多5分钟；明确点击后才打开，不因渲染／轮询／重启自动启动登录 |
| 重开 | 只重开原未过期请求，不能提交任意URL启动外部程序，不自动新建请求 |
| 取消 | 取消成功使迟到回调／领取失效；若并发时登录已先完成，显示真实状态，可退出，不伪报取消了已有登录 |
| 过期／拒绝 | 明确提示并停止该轮轮询，由人重新发起，不重复消费授权码或无限弹窗 |
| 断网未知 | 先查原请求和已保存状态，不自动补发授权或业务；无法安全继续才明确要求重扫，不伪造已登录 |
| 关闭浏览器 | 不保证等同取消；由请求到期或DSH明确取消结束 |

token、设备proof、授权码、密文及应用秘密不放进对话、可分享配置或日志，不要求用户复制授权结果。浏览器只能处理本次授权，不收到本服务长期设备token。身份及服务版本不符明确要求更新／重扫，不退回旧SSH或PC链路。

## 4. 正式切换保留什么

- 保留稳定成员账号、项目／角色、资料／业务、私人会话、项目归属、本地映射和不重发日志；不再次清库、不恢复已退役的旧系统账号。
- 新扫码链路真实验证、双平台成功CI及最终批准之后，正式切换时一次性撤销旧PC设备资格、作废旧待完成请求并关闭PC入口；各设备扫码一次，此后仍正常记住7天，不长期维护两套入口。
- 客户端仅在确认旧设备资格失效时按本插件范围清旧密文并提示重扫，不删除其他数据或让旧对话重新归属。
- 保留原项目菜单、会话固定项目、私人隔离、附件授权和恢复不重发。不能因切换重放上次消息、正式确认或未知结果的管理操作。
- 安装配套已验CI版本通过官方插件管理器，并完整退出／重开DSH，不承诺后台模块热替换；不手工覆写现用Electron依赖或强杀Host。

1. 等用户最终确认本汇总后，先非破坏性实现与隔离测试，现有PC设备仍不立即退出。所有代码提交GitHub后验证固定SHA的Windows／Ubuntu CI和原始包。

3. 新链路门槛通过后核对保留范围，在无正在执行业务写入时同步服务器／切换并一次性撤销PC设备资格；不改CPA、系统／ZeroTier或无关DSH状态。

5. A／B通过后才继续一个最小项目／角色／小附件／分析／方案／职责本人确认／任务成果／独立接收演练。所有未完成真人验收保留为待办，不按CI推定完成。
