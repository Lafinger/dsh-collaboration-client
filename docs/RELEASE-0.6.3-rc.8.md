## 本客户端改动

- 删除未使用的 `MAX_ATTACHMENT_TEXT_BYTES = 256 * 1024` 常量；该常量不参与客户端上传或读取执行，删除不改变字节传输行为。
- 同步附件指南、固定安装源及版本说明，明确服务端能力与客户端职责的边界。
- 保持现有依赖、精确宿主要求 DSH `0.2.1-rc.2` 及 lockfile 依赖图不变。

**通用文本解析不是客户端新增执行的能力。** 客户端继续只捕获当前人类消息明确选定的文件并按已有协议提供字节块；不在本地新增解码、HTML 渲染、脚本执行、外链加载、目录扫描或正文路径跟读。

## 配套服务端范围

本轮主要实现位于配套服务端 `0.7.2-rc.9`：

- 普通文本按内容而非后缀判断，严格 UTF-8（含 BOM）及带 BOM 的 UTF-16 LE／BE；拒绝二进制、NUL、非文本控制字符，不猜 GBK 或无 BOM 的 UTF-16。
- HTML 等返回原文，不渲染、不执行、不加载外链；保留原 DOCX／单帧图片专用能力，不新增 PDF／XLSX／PPTX 等二进制解析。
- 移除附件／资料／分析读取正文的256KiB限额（包括 DOCX 提取正文），不按正文大小静默截断、分页或摘要。原件每消息最多5个、总计20MiB、单文件20MiB仍保持。
- 历史附件／归档资料读取时按解析器版本刷新可再生成的派生缓存并核对原件哈希；不批量重写原件、资料身份／版本、历史分析或正式决定。
- 原件不可读时只读取用户明确指定或已有明确关联的可读说明；正式分析须显式列入范围，并分别报告原件未读与仅由说明支持的结论，不自动扩大范围。

详见[附件用法与边界](<ATTACHMENTS.md>)。这些服务端行为以服务端自身发布、部署及验证证据为准；客户端文档或安装成功不能替代其证据，也不能证明模型已逐项检查全文或完成真实运行验收。
