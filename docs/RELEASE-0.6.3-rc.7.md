## 问题与修复

用户提供的客户端会话记录显示，部分 `@文件名` 消息在本地捕获阶段即失败，错误统一为“未能核实附件、成员或项目权限”。资源管理器截图中，同名实现说明文件为 0 KB；早期失败请求还引用了与截图不一致的文件名。日志未保留底层文件系统异常，因此不能把所有失败都断言为同一个原因。25 KB 需求文件那一轮记录为用户中止，不能归为同一种上传失败。

原实现对空文件、不存在路径等抛出英文错误，插件的用户错误过滤将这些原因替换为泛化提示，导致成员无法判断应保存内容还是修正文件名。本候选保留非空文件与路径边界，修正以下反馈：

- 空文件：提示“附件文件为空，请先保存内容后再上传。”
- 不存在的路径：提示核对文件名和当前会话工作区。
- 超限、目录、文件变化、符号链接和私有状态路径：给出对应的中文原因。
- 原生附件的长度为零时也明确拒绝，不尝试读取或提交。

本次改动不生成文档内容，不把空文件伪装成上传成功，也不自动重放失败消息；用户保存真实内容后以新消息重新上传。
